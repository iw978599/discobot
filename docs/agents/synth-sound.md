# Synth sound: models, presets, filters, routes, the arpeggiator

Part of `AGENTS.md`, moved here to keep that file small. Read it before changing a synth lane's sound (models and macros, presets and the preset menu, filters, oscillators, unison, layers, modulation routes, LFOs), its swing or the arpeggiator, and keep it up to date as you would `AGENTS.md`.

- Glide (`portamento`, roadmap 18): a mono lane has always glided only legato, from a note still sounding, and a poly lane into every note from the last played. `fingered` makes a poly lane glide only into a note played while another key is held. `speed` glides at a steady rate in pitch, `glide` then being the seconds an octave takes (`glideStep` in `SynthCore`); without it every glide takes about `glide`, an exponential approach. `sync` makes the glide time a note value at the tempo (`glideSeconds` in `voiceParams.ts`), stored only when on, so its control sends 'off'. The two switches are in the defaults as false and always sent; with all three off a sound is sample for sample what it was (`portamento.test.ts`). A VAST preset's legato-only glide is now `fingered`.
- A synth lane can swing (`swing` on the lane, the `synth.swing` operation, the Swing button beside Bars): it then plays late what the drums' swing moves, as the drums are. It is a switch and not an amount of its own so that one knob sets the groove; that was the builder's choice (roadmap V11) and the owner has not confirmed it. Stored only while on, so a project that never swung is unchanged in storage, hash and sound. `swingSteps` in `services/grooves.ts` is the one place the delay is worked out, for the drums and (through `swingLate` in `drumScheduling.ts`) the lanes, in the scheduler, `renderSynthBars` (its last two arguments) and MIDI export; anything else that times notes must ask it too. The swing has a grid (`drumSwingGrid`, asked for 2026-10-22 with the swing templates): absent is sixteenths, every second one late by the amount, exactly as before; 8 is eighths, the second eighth of each beat late by twice the amount and the sixteenths beside it by the amount. It is stored only as 8, set by the `drum.swing` operation's optional `grid` (whose event always says it), taken away by `restoreContent` when undo goes back past it, and carried by every export arrangement. The templates (`SWING_TEMPLATES`, the menu beside the drums' Swing knob) set the amount and the grid together, named as drum machines count swing (50% straight, 66.7% a triplet); turning the knob afterwards keeps the grid. The notes, their MIDI out and the step light move; a step's automation stays on the step, live and in export alike. A recorded note is still written on the grid.
- A key played into a lane with the arpeggiator on (on-screen keys, the computer keyboard, MIDI in live mode) is arpeggiated for as long as it is down, through every key held as one chord, a beat at a time (`LiveArp` in `services/liveArp.ts`, one per studio). Each pulse is handed to the audio only 0.1 s before it sounds, so letting the last key go stops it at once; a key pressed or let go starts the pattern again with what is held, and a key pressed within 50 ms of another joins its beat. Every way a note is let go reaches it through `handleNoteRelease`, which is why a MIDI note into the arpeggiator is kept in `midiHeldRef` like any other. It reads the lane's sound and the tempo every beat. It is live only: nothing is recorded but the key, as before, and it is not tied to the transport's beat.
- The arpeggiator's Range (`arpeggiator.octaves`, 1 to 3) is how many octaves it runs through, for a note and for a chord alike. Absent is Auto, which is what it did before there was a choice, and the control sends 0 for it so the store's merge does not keep the old value.
- An arpeggiator given one note plays that note and the two octaves above it (`ARP_PATTERNS`); given a chord it plays the chord's own notes. Until 2026-10-13 one note gave a major chord, so a project saved before then with the arpeggiator on single notes now plays octaves. The owner asked for the change after people using the app reported it.
- A built-in preset for a synth model is made from that model's four macros (`model()` in `builtInPresets.ts`), plus only what the macros leave alone (level, sends, spread, unison, the second LFO). Loading a preset puts its own values on the lane last, so one written by hand for a model would disagree with the knobs the lane shows and jump when one is turned. A test checks each agrees.
- A built-in FM preset that is brighter for a harder note has a low `fm.index` and a route from velocity to `fmIndex` that brings it back up: the route adds its depth times the note's strength, so the index a preset is heard at is the two together. `measureMotion` in `presetAudit.ts` says how far a held preset's level moves and how wide it is; `builtInPresets.test.ts` holds the presets that promise either to it.
- Each built-in preset's `gain` is set by measurement so that presets of a kind are about as loud as each other (`LEVEL` in `builtInPresets.test.ts`). Change a preset's sound and re-measure its gain; a lane's level cannot go above 2, which is why sounds made only of filtered noise sit a little under the rest.
- A synth model's macros set only part of a lane's sound, laid over what the lane has. There are two mappings. Turning a macro uses `mapSynthModelToEngineParams`: the macros alone, so a filter slope or a unison stack someone chose on that lane stays. Moving a lane to another model uses `enterSynthModel`, which also puts back what the model it leaves may have set and the new one does not set for itself: unison off, a 12 dB slope. A model that sets something no other model does must have it put back there, or it stays behind when the lane moves on (`mapModel` sets the first oscillator's level to 1 for the same reason). Moving to the plain engine puts nothing back: it is where a model's sound is taken to be changed by hand.
- The Polysix's fourth macro, Ensemble, is the mix of the lane's chorus insert (`inserts.chorus`, with depth 0.6 and rate 0.8). The owner decided on 2026-10-13 that it moves there from the shared chorus once a lane can have effects of its own. `enterSynthModel` takes that chorus back to nothing when the lane leaves the Polysix and leaves the other inserts alone. A lane saved before, with Ensemble as its chorus send, keeps that send as it is: it is now the person's own, and no model sets any send.
- `filter.model` chooses the low-pass: `'svf'`, the state-variable filter every sound had before there was a choice (absent means this); `'ladder'` (`Ladder` in `engine/src/dsp.ts`), always four poles; or `'ms20'`, always two, whose resonance is held back more the bigger its peak has grown (`MS20_HOLD` in `SynthCore.ts`), which is its distortion. Any other filter type uses the state-variable filter whatever the model says. The sound editor offers them as further choices in the slope menu.
- Do not make a filter distort by bending what it holds on every sample: at two ticks a sample that is a steady leak, which takes level away with the resonance down and stops a peak forming at all. It was tried for the MS-20 and measured.
- `filter.highpass` is the cutoff of a two-pole high-pass before the filter, on any sound. Absent or under 20 Hz there is none, and the sound is what it was before it existed. It is plain except on the MS-20 filter, where it shares that filter's peak.
- The Minimoog and TB-303 models take the ladder when a lane moves to them (`LADDER_MODELS`, in `enterSynthModel`), not when a macro is turned, so a lane set to one of them before the ladder existed sounds as it did until the model is chosen again. The other 24 dB models keep the cascaded state-variable filter the owner listened to.
- The ladder gives back three quarters of the level its resonance takes away (`LADDER_MAKEUP`), which is far more than a real one. A lane's level stops at 200%, and a sound that lost a real ladder's 12 dB could not be brought back up; presets on it already sit at that limit.
- A sound can have up to four routes (`modMatrix`, `MAX_MOD_ROUTES`), each a source, a destination and an amount from -1 to 1. They are on top of where each LFO is already sent on the LFO tab, which is unchanged: a sound with no routes is sample for sample what it was. An LFO is a source whether or not it is switched on; the random source steps each time LFO 1 comes round and has a seeded sequence of its own, so an export is repeatable and the noise oscillator is undisturbed.
- The voice takes its parameters flat (numbers, strings and switches), so the routes cross to the audio thread as `mod1Source` to `mod4Depth`. A new source or destination needs its name in three places that must agree: the type and the lists in `engine/src/types.ts`, the lists at the top of `SynthCore.ts` (it works by position in them), and the names shown in `SynthControls.tsx`. The last source, `modWheel`, is a controller's CC 1, a live gesture like pitch bend: `SynthCore.setWheel` holds it (0 to 1, smoothed), it reaches the core by the `live` worklet message (`useSynthAudio.setLive`), it is never saved, undone or recorded, and an export plays it at 0. A CC 1 that is tied to a knob under Controller knobs moves that knob and does not also drive the wheel.
- `oscillator2.sync` hard-syncs the second oscillator to the first, and `mixer.ring` adds the two multiplied together. Both need the second oscillator switched on, and it then runs whether or not its own level is up. The sync restart is placed within the sample but is not band-limited, so a synced oscillator tuned very high aliases; that is known and not yet dealt with.
- Up to seven unison copies (`MAX_UNISON`). `unison.mix` is the level of the copies either side of the middle one, absent meaning 1; it only does anything with 3, 5 or 7 copies, which have a middle. At 1 the stack is what it was before the level existed.
- The model menu is grouped Mono, Poly and Digital (`group` on a model's definition); a new model needs one. It is a `NestedMenu` like the presets, a button named "Synth model: <model>", with Generic, which is in no group, as a row of the first list (`top`) and a model's `subtitle` as its row's hint. A row of any `NestedMenu` carries its id as `data-item`; the specs that change a lane's model share the helper `chooseModel(scope, id)`, which finds the group from `SYNTH_MODELS`.
- `mixer.osc` is the first oscillator's level, absent meaning 1. The sources are only ever brought down to the level of one, never up, so with it at 1 the mix is what it was before it existed, and turned down alone it is simply quieter.
- A tempo-synced LFO rate `N` means one cycle per 1/N note (`syncedLfoHz`). Live playback and WAV export both use it. It is still stored as a switch and that number; the LFO tab shows it as a Sync menu like the effects' (`LFO_SYNCS` in `SynthControls.tsx`: Free, a bar, down to 1/32, plus whatever other value the sound has), and while synced the Rate knob steps through every N.
- The `vibrato` LFO target is the `pitch` target scaled to one semitone at full depth. `pitch` is still an octave, so stored sounds are unchanged.
- Every built-in preset has a `kind` (`presetKinds.ts`: bass, lead, pad, keys, pluck, effects), required by the type of `createBuiltInPresets`, and `createNamedSynthPresets` takes it from the name; a new built-in preset must be given one. The preset menu is built by `groupPresets`: a group per kind that has presets, in that order, then "My presets" for anything a person saved or imported (they have no kind). `preset-kinds.spec.ts` holds the expected groups and how the menu is used; it reads the presets' names from the menu and does not hold them.
- The preset menu is a `NestedMenu` (`ui/src/rack/NestedMenu.tsx`), not a `<select>`: a button named "Synth preset: <what was last loaded on the lane>", a `menu` of the groups, and a `menu` named after the group with its presets, beside the first on a desktop and in its place under a Back row on a narrow screen. A test finds a group's row by `[data-group="Bass"]`, never by its name, because the Bass group holds a preset also called Bass; the spec files that pick a preset share the helpers `choosePreset` and `openPresetGroup`. A built-in preset is marked with a trailing ` *` that is drawn but not part of the row's spoken name. Its first list starts with a search field ("Search presets", `NestedMenu`'s `search`): what is typed replaces the groups with one list of every preset that has each word in its name or its group's name, each row's hint its group, and Enter loads the first. On a desktop a click or Enter opens the menu with the keyboard in the field, and the down arrow from there goes on to the first group; the arrows on the button open it on a row, past the field; a phone does not focus it, or its keyboard would cover the sheet. Closing forgets the search.
- A `NestedMenu`'s rows are reached with the arrow keys and are not Tab stops (`tabIndex={-1}`), so Tab leaves the menu and it closes. Its button has a fixed width with an ellipsis: what it says changes with every preset loaded, and it must never change the height of the row it stands in. Inside a unit it is not in the top bar's layer, so on a narrow screen its sheet is given a `z-index` above the bar of units; anything else that floats from inside a unit needs the same.
- The user's synth presets are read from `presetStore` after the page is up, not during the first render. Nothing is written back until they have been read (`presetsLoadedRef`), or the empty first list would replace what is stored. Anything else loaded this way needs the same guard.
- Unison copies and the 24 dB second filter stage live in `SynthCore`. One unison voice and a 12 dB slope must stay bit-identical to the sound before they existed; a test checks it.
- A sound can have a second layer (`layer`): every note is then two voices, the second with its own share of the level, tuning, filter offset, slower attack and place from side to side. `startNote` gives a voice its `layer`, and everything the second layer does in `process` is behind `second` or `layered`, so one layer is bit-identical to the sound before there could be two; a test checks it. A layered lane plays four notes, not eight. `enterSynthModel` switches the layer off for every model but the CS-80.
- Two oscillators at one pitch are in fixed phase, and a pulse and a saw set that way partly cancel. Measure a model's level (`measurePreset`) before settling on its waves.
- Octave shift range is -2 to +2 per lane and affects the on-screen keyboard, the piano roll range and the computer-keyboard piano.
